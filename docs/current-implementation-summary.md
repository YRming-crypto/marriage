# AI 婚恋网站当前实现总结

> 更新时间：2026-08-14
>
> 当前分支：`codex/design-optimization`
>
> 本文只描述当前工作区已经实现的能力。Provider 适配器存在，不代表真实短信、云存储或真实大模型已经开通。

## 1. 当前结论

项目已经具备完整的本地联系流程：

```text
OTP 注册/登录
  -> 服务端草稿与完整建档
  -> 上传并审核照片
  -> 完成 15 道关系问答
  -> 生成、确认并启用自己的 AI 分身
  -> 双向规则推荐
  -> 选择心仪对象
  -> 与对方 AI 分身完成三个了解主题
  -> 统一算法给出适合度分析
  -> 达到门槛后申请真人聊天
  -> 对方接受/拒绝
  -> SSE 真人聊天、通知和安全处置
  -> 账号安全、申诉、导出、注销和后台维护
```

本地配置 PostgreSQL 与 MinIO 后，流程可跨 API 重启恢复。默认 AI 使用确定性 Provider；配置 OpenAI-compatible Provider 后才调用真实模型。

准确定位仍是“可运行、可持久化、可部署联调的联系型 Demo”。它不具备生产级合规、分布式风控、高可用和大规模运营能力。

## 3. 账号、建档与审核

已实现：

- 手机号 OTP 自动注册/登录，30 天 HttpOnly、SameSite Cookie 会话。
- 内存手机号索引未命中时会先从 PostgreSQL 恢复已有账号，避免重复注册和会话外键错误。
- 同手机号 60 秒发送冷却、同 IP 10 分钟 20 次、单验证码最多 5 次错误。
- 查看登录设备、撤销单个会话、保留当前会话并退出其他设备。
- 服务端建档草稿保存/恢复，以及浏览器按用户隔离的本地草稿。
- 基本资料（含吸烟情况和子女情况）、交往偏好和 15 道关系问答；服务端要求当前 15 题全部非空并忽略旧题键。
- JPEG、PNG、WebP 照片上传，单张最多 8 MB、每人最多 6 张；支持主照片、删除和状态查看。
- 管理员审核或退回资料与照片，退回原因会返回用户。
- 资料可见范围：`private`、`approved_only`、`public`。
- 游客只看到 `public` 和无可见性字段的演示会员；`approved_only` 只允许通过匹配的已登录用户访问详情或推荐。
- 公开匹配大厅支持城市、年龄、仅看有照片、吸烟情况、子女情况筛选，以及最近活跃、最新加入和年龄排序；正式会员加入时间来自真实账号创建时间。

正式用户进入会员投影必须同时满足：

1. 账号状态为 `active`。
2. 资料审核为 `approved`。
3. 至少一张照片审核为 `approved`。
4. 资料可见范围不是 `private`。
5. 自己的 AI 分身状态为 `enabled`。

资料重新提交后立即进入待审，会员投影下架，已启用的 AI 分身自动暂停。审核通过后仍需用户重新确认并启用 AI 分身。

## 4. AI 分身和知识管理

已实现：

- 从资料、15 道问答和交往期待生成授权摘要。
- AI 分身状态：`pending`、`enabled`、`paused`、`revoked`。
- AI 知识条目创建、修改、删除，支持关键词、主题和治理状态。
- 知识治理状态区分允许、敏感和禁止；禁止知识不能进入可用版本。
- AI 分身版本生成、激活、回滚和持久化。
- 会话回答优先使用当前激活/陈旧版本的治理知识；没有可用版本时使用授权摘要 Provider。
- 对明显手机号信息进行输入/输出限制。
- AI 会话、消息、知识、版本和模型调用记录可写入 PostgreSQL。

前置条件：当前用户必须启用自己的 AI 分身才能获取正式推荐；目标用户必须启用 AI 分身才能出现在正式会员投影并接受 AI 会话。

本地默认 `AVATAR_MODEL_PROVIDER=deterministic`，不是生产大模型。OpenAI-compatible 适配器需要真实 endpoint、API key 和 model name。

## 5. 匹配和心仪门槛

当前统一算法版本：`bidirectional-rules-v1.0.0`。

算法流程：

1. 双向检查双方的性别、年龄、城市/异地、婚姻状态和关系目标硬条件。
2. 任一方向不接受时，候选人不进入推荐结果，也不能通过适合度准入。
3. 对通过硬条件的候选人计算年龄、地点、目标、婚姻经历、看重品质和资料可信度。
4. 返回 `score`、`reasons`、`factors` 和 `algorithmVersion`。
5. 推荐列表和 AI 会话分析调用同一算法，并保存匹配快照。

公开会员和推荐接口都使用服务端 v3 无状态压缩签名游标分页。游标绑定当前筛选/排序并携带 30 分钟冻结结果集，在应用加密密钥不变时可跨 API 重启继续，因此翻页期间排序字段变化、新增或删除会员都不会造成重复或遗漏；网页匹配大厅支持加载更多、保留已显示结果、按会员 ID 去重、忽略过期筛选请求，并在游标失效时自动刷新当前筛选首屏。

这是一套确定性规则算法，不是训练模型、向量召回或经过真实婚恋效果验证的正式算法。前端展示可读理由，不展示 Prompt 或内部权重。

正式会员联系门槛：

- 创建 AI 会话前必须先选择并保持该会员为心仪对象，否则返回 `409 INTEREST_REQUIRED`。
- 发起真人聊天申请时再次检查心仪状态，防止会话期间取消后绕过。
- AI 会话需完成生活、关系、沟通三个主题。
- 双向规则分数需达到 `70`。
- 资料/照片审核、AI 分身状态和屏蔽关系必须在每个关键入口仍然有效。

演示会员保留少量本地体验例外；正式 PostgreSQL 用户不依赖演示例外。

## 6. AI 聊天、真人聊天和通知

### AI 分身聊天

- 问题最多 500 字。
- 每用户滚动 10 分钟最多发送 20 条 AI 问题；超过返回 `429 AVATAR_MESSAGE_RATE_LIMITED`。
- 限流窗口在单 API 进程内，重启会清空，不是分布式配额。
- 记录用户消息、AI 回答、识别主题和完成进度。
- AI 分身生成纳入全部 15 道已回答的关系问答，不再截断为前 8 道。
- 模型失败后保留原问题；用户可在原消息上明确重试，成功后解决失败任务且不重复保存问题。
- 用户可查看自己的 AI 会话并主动结束本次了解；结束后旧会话不能继续提问，再次进入同一对象时开启新一轮会话并保留历史。
- AI 聊天网页可按对象列出已结束轮次、只读查看历史消息并返回当前轮次；举报历史回答会关联正确的历史会话和消息证据。
- 阶段分析返回 `score`、`algorithmVersion`、`factors`、共同点、建议话题和真人准入状态。

### 真人联系

- 满足门槛后发起申请，对方可接受或拒绝；申请有效期为 7 天，过期后不能处理但可重新申请。
- 双方从两个方向分别申请并接受时，按无方向用户对复用一个会话。
- PostgreSQL 使用唯一约束和事务避免“申请已接受但会话未创建”的半状态。
- 文本消息最多 1000 字；`clientMessageId` 必填、校验格式，并按发送者和会话去重。
- 网页在发送失败后为相同会话和正文复用原 `clientMessageId`；API 拒绝同一标识对应不同正文，避免网络重试产生重复或静默丢失内容。
- 真人消息每用户每分钟最多 30 条，幂等重试不重复计数；限流窗口属于单 API 进程。
- 网页对联系方式给出隐私提醒；银行卡、转账、汇款、保证金等资金风险内容在网页禁止提交，并由 API 再次拦截。
- 发送消息及接受申请前重新检查双方账号状态，接收方停用后不能继续联系。
- `GET /api/realtime/events` 提供 SSE 事件流。
- 支持新消息、通知、在线状态、5 秒自动过期的输入状态和消息已读事件。
- API 重启或事件历史过期时发送 `resync`，网页重新拉取会话与通知；已结束或屏蔽的会话不能发布输入状态。
- 支持结束/恢复真人会话，以及发送者撤回自己的近期消息；撤回后双方历史均不再返回原文。
- 消息、送达/已读回执、通知和会话状态可持久化；在线状态和输入状态是进程内瞬时状态。

当前没有 WebSocket、离线 Web Push、短信提醒、图片/语音/文件消息或视频通话。

## 7. 举报、屏蔽和后台

举报请求可附带：

- `avatarSessionId`：AI 分身会话证据。
- `conversationId`：真人会话证据。
- `messageId`：具体消息证据。

服务端会验证：AI 会话属于举报人且目标用户正确；真人会话同时包含举报人和被举报人；真人消息属于该会话且由被举报人发送。缺少所属会话的孤立消息 ID 会被拒绝。证据字段持久化并出现在管理员举报列表中。

屏蔽采用双向有效判断：任一方屏蔽后双方不再互相展示，已有真人会话改为 `blocked`，关键联系入口全部拒绝继续联系；只有双方所有方向的屏蔽都解除后会话才恢复。PostgreSQL 模式将屏蔽记录和会话状态放在同一事务中。

管理员后台已实现：

- 资料和照片审核。
- 用户列表、管理员停用和恢复。
- 停用账号申诉审核。
- 举报证据查看和处理。
- 会员发布待审核生活动态、查看和删除自己的动态；每条最多 9 张图片，图片使用独立 `moments/` 对象命名空间，不占资料相册额度。
- 内容草稿、编辑、发布、下线和删除。
- AI 回复失败任务的脱敏查看和人工重试；用户原始问题不会出现在后台列表中。
- 管理员操作审计。
- 系统摘要和手动维护清理。

账号、申诉、审计、运维和内容管理只允许 `admin`；`moderator` 仅可处理资料、照片和举报。内容状态持久化与管理员审计当前按顺序写入，不在同一个数据库事务中；极端情况下若内容写入成功而审计写入失败，接口可能返回失败但内容状态已经生效。该单实例 Demo 不扩展生产级跨步骤事务，正式运营前必须补充同事务写入或可靠补偿与对账机制。

管理员停用带 `suspensionSource=admin`，OTP 登录不会自动恢复。用户仍可建立受限会话并进入 `/me/security` 查看账号状态、设备和申诉；不能进入匹配或聊天业务。用户主动暂停则允许后续 OTP 登录恢复。

## 8. 账号生命周期和数据导出

### 注销

- 用户提交注销后进入 7 天冷静期，可在到期前撤销。
- 到期后再次 OTP 登录会先执行注销并拒绝恢复。
- 管理员可通过 `POST /api/admin/operations/cleanup` 批量执行到期注销。
- 执行后账号设为 `deleted`、停用来源和注销时间清空、所有登录会话撤销、会员投影下架。
- 当前是逻辑注销，不是立即物理删除全部资料、聊天、举报和审计记录；文档不得描述为彻底擦除。

### 数据导出

导出即时生成 JSON，24 小时内可下载。同一用户已有未过期导出时不会重复生成。内容覆盖：

- 账号、资料、建档草稿和照片元数据。
- 心仪记录、匹配快照、AI 分身摘要。
- AI 知识、版本、模型调用记录、AI 会话和 AI 消息。
- 真人聊天申请、会话、消息和消息回执。
- 通知、举报、屏蔽、账号申诉。
- 内容点赞和活动报名。

导出正文在 PostgreSQL 中以应用层密文保存；过期后下载接口返回 `410`，维护清理会把正文置空并标记 `expired`。

## 9. 数据和迁移

内存模式适合快速演示：注册账号和业务状态随 API 重启清空，Data URL 照片对象也会丢失。

PostgreSQL 模式持久化账号、资料、审核、草稿、匹配、AI 知识、聊天、通知、内容、安全和运维记录；S3/MinIO 分别保存资料照片和动态图片对象。动态图片通过仅允许已发布内容、作者或后台读取的站内接口提供；上传期间保持不可发布状态并先持久化预留对象键，删除动态或注销账号时先下线记录、再清理对象、最后移除记录，失败后仍可重试且不会公开破图。到期注销还会在删除资料照片对象前先持久化隐藏资料和照片。手机号、关系问答、AI/真人聊天正文和导出正文使用应用层加密或哈希保护。丢失 `APP_ENCRYPTION_KEY` 后历史密文和旧分页游标不可读。

会员最近活跃时间来自真实登录 Session。活动时间按分钟节流写回 PostgreSQL，并在 API 重启水合账号时恢复到公开会员投影，避免最近活跃排序在重启后回退。

## 10. 维护方式

管理员接口：

- `GET /api/admin/operations`：查看健康摘要和最近维护运行。
- `POST /api/admin/operations/cleanup`：依次清理到期注销、过期 OTP、过期会话和过期数据导出。

维护运行记录包含每个清理目标的成功/失败和数量，并写入管理员审计。任务不由仓库自动定时触发，必须通过管理员页面/API、计划任务或外部调度执行。

数据库和照片必须作为同一恢复点备份。仓库脚本会在同一恢复集中处理 PostgreSQL dump 与完整 S3/MinIO 对象桶，并生成 SHA-256 清单；定时调度、备份加密、异地保存和告警仍由部署方补齐。

## 11. 明确排除和剩余边界

按当前项目范围明确排除：

- 实名认证、身份证、活体检测、人脸核验。
- 短信签名和模板审批、正式短信供应商账号开通。
- 生产备案和完整法律合规落地。
- 生产级分布式风控、WAF、高可用、多地域和大规模运营。
- 内容状态与管理员审计等多步骤写入的生产级原子事务、补偿和自动对账。

仍属于技术增强但不是当前完整本地流程缺口：

- 分布式 OTP/AI 限流、设备指纹和每日额度。
- 图片压缩、EXIF 清理、预签名直传、自动内容审核和 CDN。
- 算法离线评估、A/B 测试和真实效果验证。
- Web Push、移动端推送、多媒体消息和会话归档。
- 外部监控、错误追踪、自动备份调度、密钥轮换工具和高可用编排。

## 12. 最终定位

> 当前代码完成了要求范围内的本地端到端流程，包括前台联系、后台管理、账号生命周期和维护；它适合开发、演示、联调和单实例验收，不可宣称已完成实名合规、真实短信审批或生产级大规模运营。

交付形态仅包含响应式网页、网页管理后台、API、PostgreSQL、MinIO、Docker、测试和文档，不包含 Electron、Tauri 或其他桌面客户端。
